## arm (사전 등록, 3개 + 참조)

| arm | 학습 | 추론 |
|---|---|---|
| `parent` | extreme_4.0: 블록 가중(24h 최대 ≥550 또는 6h 상승 ≥100 → ×4, 평균 1), 회귀 | 그대로 |
| `reference` | 같은 회귀, 비가중 | 그대로 |
| `hist_unweighted` | HL-Gauss 16-bin 분류, 비가중 | bin 평균 |
| `hist_weighted_raw` | HL-Gauss 16-bin 분류, **pointwise** 가중 w(y_h)=4 (y_h≥550), 평균 1 정규화 | bin 평균 |
| `hist_weighted_corrected` | 위와 **같은 학습 1회** | p(k\|x) ∝ p_w(k\|x)/w_k 로 정확히 역보정 후 평균 |

`hist_weighted_raw`와 `hist_weighted_corrected`는 같은 부스터를 두 번 읽는 것이므로
추가 학습 비용이 없다. 따라서 실제 학습은 arm당 1회, 창당 2회(비가중 1 + 가중 1)다.

## 히스토그램 헤드 (축 변경 지점)

- 출력 표현: 스칼라 회귀 → K=16 범주 확률. 손실: 가우시안 평활 soft label에 대한
  교차엔트로피(HL-Gauss). 점예측은 예측 히스토그램의 평균.
- bin 경계(고정, 550 km/s가 정확한 경계): 240, 290, 340, 390, 440, 490, 520,
  **550**, 580, 610, 640, 680, 730, 800, 900, 1000, 1150.
  550 위아래 어느 bin도 경계를 걸치지 않으므로 w(y)는 bin마다 상수이고, 역보정이
  이산 목표에 대해 정확하다.
- 평활 폭: σ = 0.5 × 해당 bin 폭, [10, 50]으로 절단. soft label은 bin 구간에 대한
  가우시안 질량(정규 CDF 차).
- bin 대표값: 그 창 학습 목표의 bin 내 조건부 평균(빈 bin은 중점). 두 arm이 같은
  대표값을 공유하므로 비교에 영향이 없다.
- 헤드 구조: 부모의 24h 블록 설계(237열)를 그대로 쓰고, block×horizon마다 K-class
  `multi:softprob` 부스터 1개(창·arm당 72개). 트리 구조 공유 여부는 축이 아니므로
  부모의 horizon별 자유도를 유지한다.
- 정규화 단위 변환(사전 도출): K-class softmax 헤시안 p(1−p)는 제곱오차 헤시안의
  약 1/K이다. 따라서 `reg_lambda = 5·h_ref`, `min_child_weight = 20·h_ref`,
  h_ref = (1/K)(1−1/K) = 0.0586. 이는 데이터를 보지 않고 K만으로 정한 단위 변환이며,
  같은 숫자를 그대로 쓰면 히스토그램 헤드에 부모보다 약 17배 강한 축소가 걸린다.
  구조 설정(depth·lr·rounds·subsample·colsample)은 부모와 동일하다.
- pointwise 가중을 쓴 이유: extreme_4.0의 블록 가중은 24h 궤적 전체의 함수라
  y_h만의 함수가 아니어서 정확한 역보정이 불가능하다. 축을 살리기 위해 가중을
  y_h만의 함수로 정의한다(할당서의 지적).

## 지표와 판정

- 창마다 목표값 기준 <550 / ≥550 MSE, 원시 총 MSE. 재가중
  `MSE_rw = (1−p)·MSE_<550 + p·MSE_≥550`, p는 그 창 학습 목표 중 ≥550 비율.
- pooled D1–D3: 세 창의 쌍을 합쳐 같은 식으로 계산하고, p는 창별 p를 평가 쌍 수로
  가중 평균한다.
- 통과 조건(PROTOCOL 그대로): (1) pooled MSE_rw ≤ 0.99 × 부모, D1–D3 중 2개 이상
  창에서 개선. (2) pooled MSE_≥550 ≤ 0.95 × 비가중 참조. (3) 창 C에서 (1)(2) 방향 유지.
- 후보는 `hist_weighted_corrected` 하나로 고정한다(사전 등록). 다른 arm은 축 분리
  진단이며, 내부 통과 시에도 후보를 바꾸지 않는다.
- 내부 통과 시에만 F1/final 재적합 후 `submit.py --dry-run` 1회. 업로드 없음.

## 정직성 고지

- Top30 feature는 공개 공식 permutation importance로 골랐고, D1–D3/C는 과거 실험에
  노출됐다. 어떤 결과도 untouched holdout 증거가 아니다.
- 사전 확인 1건: 정규화 단위 변환을 정당화하려고 D1의 단일 horizon(h=36, block 1)에서
  학습 곡선만 확인했다. 변환식은 그 확인 **이전에** K로부터 유도했고, 확인은
  "변환판이 underfit하지 않다"만 보였다. arm·bin·판정식은 이 확인과 무관하게 위에
  고정했다.
- 학습 곡선은 매 round의 train/valid CE와 km/s RMSE를 저장한다. valid는 평가 창이며
  선택에 쓰지 않고 진단으로만 보고한다.

## 수정 등록 (2026-10-28T15:52Z, 어떤 창 지표도 계산되기 **전**)

실행 중 측정한 실제 비용으로 900 rounds 일정이 캠페인 공유 CPU 예산에서 약 15시간이 되어
실행 불가로 판정했다. 아래와 같이 사전 등록을 수정한다. **어떤 arm의 창 지표도 이 시점에
계산되지 않았다**(부모의 D1 재적합만 완료됐고 점수화하지 않았다).

- `rounds`: 900 → **300**, 모든 arm에 동일 적용(부모·참조·히스토그램).
- 근거: 사전 확인에서 두 목적함수 모두 held-out 손실이 약 300 round에서 최저이고 그 뒤로는
  악화됐다(회귀 valid RMSE 73.48@300 → 74.19@900; 히스토그램 69.15@300 → 70.85@900).
- 방향성: 부모를 300 round로 재적합하면 **부모가 더 강해진다**(그 horizon 기준 73.48 < 74.19).
  따라서 이 변경은 후보에게 불리한 방향이며, 비교를 후보 쪽으로 유리하게 만들지 않는다.
- 부모의 출판된 900-round 재적합(D1)은 이미 산출물로 남아 있어 `aborted_20261028_v1`에서
  충실도 진단으로 함께 보고한다. 판정에는 쓰지 않는다.
- 창·행·seed·bin 격자·arm·판정식은 바꾸지 않는다. 실행 ID는 `full_20261028_v2`.
- `hist_unweighted`(축 (i) 진단)는 비용 때문에 D1과 C 두 창에서만 수행한다. 판정 조건에는
  쓰이지 않는다.
