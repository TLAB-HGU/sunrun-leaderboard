# sunrun leaderboard execution

Every experiment is posted to the leaderboard Space before it runs, and when it finishes its result is submitted to the leaderboard, which retires its 대기/진행 entry (user instruction, 2026-10-28/29; this replaces the no-upload rule for leaderboard results). Register with `/home/t-lab01/sunrun/.venv/bin/python lbstatus.py set <experiment> --status 대기 --desc "<what it tests>"`, launch with `lbstatus.py run <experiment> -- <command ...>`, then submit the result and run `lbstatus.py sync`. Internal or development gates are recorded only; they never skip F1/F2/F3 evaluation or the submission (user instruction, 2026-10-29; periods F1 = Jan-Mar, F2 = Apr-Jun, F3 = Jul-Sep since 2026-10-31).

Every submitted result must carry an architecture link: `meta.yaml` needs `architecture_url` naming the study source that defines the model (`research/<study>/<file>` at a pinned commit of `TLAB-HGU/sunrun-leaderboard`), and `submit.py` records it in the Space's `architecture-code.json` in the same commit as the page. The board's `code` column must never show the replay script (`scripts/<member>/<experiment>/<submission-key>.py`, user instruction 2026-11-01). After a submission, `architecture_code.py check` must report 0 rows without an architecture link; `architecture_code.py add` + `publish` repair rows published before this rule.

No hashes (user instruction 2026-11-02): never compute, record or verify sha256 or any other file hash. `submit.py` handles the submission key internally.
