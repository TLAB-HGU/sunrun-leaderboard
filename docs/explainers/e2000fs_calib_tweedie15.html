0 · 한눈에

바꾼 것: 가중 제곱오차 → Tweedie deviance (p = 1.5)

기존 레시피(dirmo-24 pointweight4)는 정답이 550 km/s 이상이면 오차를 4배로 세는 가중 제곱오차입니다. 이 실험은 같은 자리에 분산이 평균의 p제곱에 비례한다고 보는 Tweedie deviance(p = 1.5, S = 500 km/s)를 넣고, 마스크·라운드·시드가 같은 짝(paired) control을 함께 학습해 두 손실만 비교했습니다.

읽는 법. 주황 = Tweedie arm, 회색 = point4 control. 모든 숫자는 runs/tweedie15_v1/의 예측 배열·모델·손실 로그·results.json에서 다시 계산했고, 실행 로그에 기록된 값과 1e-6 이내로 일치하는지 확인한 뒤 넣었습니다.
1 · 대상과 정답

예측 대상은 “시점 t의 다음 72시간 풍속 72개”

원점(origin) t는 마지막 입력이 관측된 정시입니다. 모델은 t까지의 정보로 t+1h … t+72h의 ACE 속도를 한꺼번에 냅니다. 학습 라벨은 t+144h ≤ 학습 컷오프인 원점만 씁니다 — 72시간 예측이 모두 성숙하고도 72시간이 더 지난 원점만 남기는 마스크입니다.

마스크가 144시간인 이유는 두 몫이 겹치기 때문입니다. 72시간은 “예측 구간 자체가 성숙하는 데” 필요한 시간이고, 나머지 72시간은 “그 뒤에 관측이 확정되는 데” 필요한 여유입니다. 72시간만 요구하면 마지막 72시간의 정답이 학습 시점에 아직 확정되지 않은 상태로 들어갈 수 있습니다.

학습에 쓰는 원점 = { t : t + 144h ≤ 컷오프 }   // 컷오프: F1 2026-02-26, F2 2026-05-29
학습 라벨 = y[t, 1 … 72]   // 원점마다 24×3 벡터 하나

공식 창 (F1 + F2)

F1은 2026-02-28 23:00 ~ 05-28 23:00, F2는 05-31 23:00 ~ 09-26 23:00의 매시간 원점입니다(사이에 72시간 공백). F1 학습 컷오프는 02-26이라 3~5월 원점은 순수 예측 구간입니다.

정답의 생김새

y[t, h] = speed( t + h ),   h = 1 … 72
전체 셀 = 4,970 × 72 = 357,840개  // 결측 0
고속(≥550) 셀 비율 =  // 673셀/시점 × ...

평가지표는 이 셀들에 대한 MSE와, 그중 정답이 550 이상인 셀만 모은 MSE입니다. 뒤에서 보듯 두 지표의 요구가 서로 다릅니다.

2 · 입력

30개 피처 → 237열, 3블록

입력은 이 실험에서 고정입니다. 캐시된 피처(names.json: 상수 90종 + 시간별 20종) 중 미리 고른 Top30을 쓰고, 블록마다 상수 21 + 시간별 9 × 24시간 = 237열을 만듭니다. 이미지·ACE 피처가 어떻게 만들어지는지는 자매 문서 detpool_gpd 페이지 1~6절에 바텀업으로 정리돼 있습니다.

상수 21종 T0 한 값

시간별 9종 h마다 값

원래 시간별 피처는 20종(27일 회귀 4 + 경도 줄 15 + Enlil 1)이고, 이 9종이 선택된 것입니다. 나머지 11종은 Top30에서 탈락했습니다.

Xblock = [ C(21) , E(24 × 9 = 216) ] = 237  ·  블록 3개 → 출력 24 × 3 = 72
E는 reshape(N, -1)로 시간 우선으로 펼칩니다: X[22..30] = h1의 9개, X[31..39] = h2의 9개, …
왜 72시간을 한 모델로 내지 않고 3개로 나누나. 24개 출력까지는 “리프 하나가 24차원 벡터”로 감당이 되지만, 72개를 한 리프에 넣으면 한 잎이 너무 많은 자유도를 갖고 표본이 희박해집니다. 3블록 분할은 point4 원형 레시피이고 이 실험은 그 결정을 바꾸지 않았습니다 — 손실만 교체하는 것이 목적이기 때문입니다.

물리적 하한 1 km/s, 상한 3,000 km/s. 이 clip은 두 arm에 동일하므로 비교에 영향을 주지 않습니다.

4 · point4가 만드는 편향

“고속에 4배 가중”은 최소점 자체를 옮깁니다

control의 손실은 L = ½·w·(μ−y)², w = 4 (y ≥ 550) 또는 1이고, 코드는 w를 horizon별 평균 1로 정규화합니다. 이 손실을 μ에 대해 최소화하면 조건부 평균이 아니라 가중 평균이 됩니다.

∂L/∂μ = Σ w(μ − y) = 0  →  μ* = Σ w·y / Σ w  // E[w·Y]/E[w] — 4배 가중된 꼬리에 끌린 값

정답이 낮은 셀은 가중치가 1, 높은 셀은 4이므로 μ*는 “평균보다 위쪽”으로 밀립니다. 즉 저속 구간에서 과대예측이 구조적으로 생깁니다. 실제 잔차(bias = 예측 − 정답)가 그것을 보여 줍니다.

손 계산: 가중 평균이 어디로 가나

같은 원점·같은 h에서 두 학습 샘플만 있다고 하면 y=500 (w=1), y=650 (w=4)
μ* = (1·500 + 4·650) / (1 + 4) = 620
가중치가 없었다면 (500 + 650)/2 = 575 → 꼬리 하나가 답을 45 올렸습니다.

실제 학습에서는 horizon마다 w를 평균 1로 정규화합니다. 그래서 “4배”의 실효 크기는 그 horizon의 고속 비율에 따라 달라집니다.

실제 정규화 계수 (학습 라벨, 원점)

h=1 기준: 고속 비율 14.61% → 평균 w = 1 + 3×0.1461 = 1.438 → 고속 셀의 실효 가중치는 4/1.438 = 2.78, 나머지는 1/1.438 = 0.695. 비율은 그대로 4 : 1이고 크기만 2.78 : 0.695로 줄어듭니다 (평균 1을 맞추기 위한 재조정).

control은 F1·F2 모두 350 미만에서 +60~+72 km/s 과대예측이고 고속에서는 −32~−49로 과소예측입니다. 한 방향으로 치우친 게 아니라 “위로 밀린 뒤 꼬리에서는 여전히 부족한” 모양입니다. Tweedie는 이 편향을 겨냥한 대안입니다.

5 · Tweedie 손실

분산이 평균의 p제곱이라고 보는 손실

Tweedie 분포는 Var(Y|X) = φ·μp로 분산이 평균에 종속된다고 봅니다. p = 1이면 포아송, p = 2면 감마, 1 < p < 2면 0과 양수 사이에 질량이 있는 연속 분포입니다. 태양풍 속도는 항상 양수이고 오른쪽으로 길게 치우친 값이라 p = 1.5를 씁니다.

d(y, μ) = 2 · [ y2−p/((1−p)(2−p)) − y·μ1−p/(1−p) + μ2−p/(2−p) ]
p = 1.5  →  d(y, μ) = 4 (√μ − √y)² / √μ  // 제곱오차가 아니라 “상대오차”에 가깝다

코드의 그래디언트 (그대로)

mu = clip(pred, 1, 3000)
s = 5001.5
g = s · ( mu1−p − y · mu−p )
h = s · ( (1−p)·mu−p + p·y·mu−p−1 )
h = max(h, 10−6·s)

정리하면 g = (S/μ)p(μ−y). 제곱오차의 (μ−y)에 μ의 함수인 계수가 붙은 모양입니다.

왜 Sp를 곱하나

μ ≈ 450에서 (S/μ)1.5는 1.17 정도이고, μ가 커지면 1보다 작아집니다. 그대로 두면 그래디언트 스케일이 수천 단위로 흔들려 reg_lambda = 5의 의미가 바뀝니다. 상수 Sp(= 5001.5)를 곱해 그래디언트를 O(1)로 유지합니다. 상수배는 최적점을 움직이지 않습니다.

S1.5 = 500·√500 = 11,180.34

헤시안 하한도 같은 상수에 비례해 겁니다. Tweedie 손실은 (y, μ) 조합에 따라 헤시안이 0 이하가 될 수 있어서입니다.

이 손실의 성질 세 가지

  • 최소점이 정확히 y: μ = y에서 d = 0, ∂d/∂μ = 0. 가중치로 답을 비틀지 않습니다.
  • 상대오차: d ≈ 4(√μ−√y)²/√μ 이므로 같은 100 km/s 오차라도 μ가 작을수록 크게 벌점화됩니다.
  • 고속은 싸게 벌점화: 같은 150 km/s 오차의 deviance 비용이 μ = 300에서 3.5, μ = 700에서 1.1입니다. 게다가 정규화 λ/c가 고속에서 커져 보폭까지 줄어듭니다 — 꼬리 악화의 두 원인입니다.

리프 값은 결국 얼마나 움직이나

v = −G/(H + λ) = −(μ − y) / ( k + λ/c )
c = (S/μ)p,   k = (1−p) + p·y/μ   // λ = 5

계수 c가 G와 H에 함께 걸려 있어 비율에서 상쇄됩니다 — “Sp를 곱했으니 학습률이 바뀐다”는 해석은 틀립니다. 대신 두 가지가 남습니다: ① k는 y/μ에 따라 변하고(y < μ/3이면 음수 → 헤시안 clip), ② λ/c는 c가 작아지는 고속에서 커져 정규화가 상대적으로 세집니다. 아래 표에서 λ=0일 때와 λ=5일 때 보폭의 방향이 반대로 바뀌는 것을 볼 수 있습니다.

중요한 구분. 이 손실은 “고속을 더 세게 학습”하는 장치가 아닙니다. 위 표처럼 μ가 클수록 같은 오차의 그래디언트와 벌점이 작아집니다. 대신 저속·중속에서 상대오차를 크게 벌점화합니다.
6 · 그래디언트 수치

같은 150 km/s 과소예측, 예측 수준에 따라 얼마나 세게 밀리는가

계산 예시 (y = μ + 150)

읽을 것 세 가지. ① |g|는 μ가 커지면 작아집니다(323 → 91) — 계수 (S/μ)1.5의 효과. ② 그런데 이 표의 −g/h(정규화 없음)는 μ가 커지면 커집니다 — 헤시안 k도 함께 작아지기 때문입니다. ③ 손실이 실제로 매기는 값은 마지막에서 두 번째 열입니다: 같은 150 km/s 오차의 deviance 비용이 μ=300에서 3.5, μ=700에서 1.1 — 고속 오차를 3배 싸게 봅니다. control의 제곱오차는 22,500으로 μ와 무관합니다(가중치가 붙으면 4배).

실제 예측에서 잰 값 (F1+F2 전체)

예측값 μ 구간별로 평균 |오차|와 평균 |g|입니다. Tweedie의 |g|는 구간이 올라가도 6.4 → 3.1로 커지지 않고, control은 4배 가중을 적용하면 0–350 구간 23.4에서 550–650 구간 89.8로 3.8배 커집니다. 같은 데이터에서 두 손실이 서로 다른 곳에 힘을 싣고 있다는 직접 증거입니다.

7 · 학습 곡선

900 라운드 동안 무엇이 좋아졌나 — 기록된 지표는 MSE다

학습 로그(losses_*.csv)의 train/valid 열은 목적함수 값이 아니라 RMSE²입니다. XGBoost가 커스텀 목적함수에서도 기본 eval_metric='rmse'로 기록했기 때문입니다. 즉 최적화하는 것(Tweedie deviance)과 기록되는 것(MSE)이 다릅니다 — 이 실험의 결과를 읽을 때 핵심입니다.

Tweedie trainTweedie valid control traincontrol valid

블록별 최종/최적 (internal, valid MSE)

읽는 법

  • Tweedie의 train MSE도 control보다 높습니다 — 목적이 다르니 당연합니다.
  • valid MSE가 최저인 라운드는 control이 훨씬 이릅니다(과적합 신호). 그런데도 900 라운드를 그대로 씁니다. 라운드 수는 사전 고정값입니다.
  • 이 곡선만 보고 “Tweedie가 더 나쁘다”고 결론내면 틀립니다. 최종 채점은 F1/F2에서 따로 합니다(10절).
  • train과 valid의 간격이 곧 과적합의 크기입니다. control은 164라운드에서 valid가 최저(4,036)인데 900라운드에서는 4,111로 +75 나빠집니다. Tweedie는 826라운드에서 최저(4,238)이고 900라운드에서 4,257로 +19만 나빠집니다 — 곡선이 더 평평합니다.

9 · 예측 차이와 밴드별 성적

두 arm은 평균 −15 km/s만큼, 그러나 꼬리에서 크게 갈립니다

(Tweedie − control) 예측 차이 분포

밴드별 MSE · deviance · bias

같은 셀을 정답 크기로 나눠 본 표입니다. 저속·중속에서는 Tweedie가 크게 이기고, 고속(≥550)에서는 크게 집니다. deviance까지 함께 나빠지므로 “다른 지표로는 이겼다”는 식의 변호도 성립하지 않습니다.

왜 꼬리에서 지는가. 두 겹입니다. 첫째, Tweedie의 손실은 같은 절대오차에 대해 고속에서 더 싼 값을 매깁니다 (6절 마지막 표: 오차 150의 비용이 μ=300에서 3.5, μ=700에서 1.1). 고속을 맞히는 일의 우선순위가 낮아진다는 뜻입니다. 둘째, 정규화 λ/c가 고속에서 커져 보폭이 줄어듭니다(5절 표). 결과적으로 정답 ≥550 셀에서 Tweedie의 bias는 F1 −57.5, F2 −76.3으로 control(−31.7, −48.6)보다 더 크게 과소예측합니다. 반대로 350 미만에서는 과대예측이 줄어 (F1 +71.7 → +54.7) 저속 성능이 크게 좋아집니다.

셀 하나하나에서는 두 손실이 어떻게 다른 점수를 주나

F1 그리드에서 control 오차가 큰 순서로 0.1%·1%·10%·중앙 위치의 셀을 뽑아, 같은 (정답, 예측) 쌍에 제곱오차와 Tweedie deviance를 나란히 적었습니다.

가운데 줄(중앙값 위치)이 이 실험의 축약입니다: 정답 625에 control 587, Tweedie 514 — 제곱오차는 1,412 대 12,315인데 deviance는 0.096 대 0.956입니다. 손실이 작다고 채점이 작지 않고, 그 반대도 마찬가지입니다.

원점 두 개를 나란히 — 이긴 사례와 진 사례

10 · 채점과 사전등록 판정

F1·F2에서 한 번만 채점한다

internal은 선택용 창(2025-12-04 ~ 2026-02-22, 648 원점)이고, F1·F2는 제출 창입니다. 통합(pooled)은 두 폴드를 셀 수로 가중한 값입니다.

사전등록 3조건

사전 규칙은 “총 MSE 개선 + 고속 MSE 악화 없음 + 350 미만 bias 개선”이었습니다. 1·3은 통과, 2는 실패입니다.

내부 창과 공식 창의 부호가 반대

internal: MSE 8,115.5 (control 7,660.4) → +5.9%
official: MSE 3,227.6 (control 3,491.0) → −7.5%

내부 창만 보고 판단했다면 이 실험은 버려졌을 것입니다. 기록된 교훈은 “내부 창은 공식 창의 방향을 예측하지 못했다”이고, 그래서 내부 게이트로 공식 채점을 막지 않는다는 규칙이 이 실행 뒤에 굳었습니다.

당시 보드 맥락. 통합 총 MSE 3,227.6은 직전 보드 선두(3,249.8)보다 좋고, 고속 MSE 9,426은 control(5,764)과 당시 선두(8,903)보다 나쁩니다. 즉 “전체는 최고, 꼬리는 최악”인 교체였습니다.
11 · 최종 예측에서 하는 일

이 arm은 detroute의 body, 그리고 detpool의 base입니다

tweedie15의 72시간 예측은 그대로 제출되지 않고 다른 두 실험의 재료가 됩니다.

detroute: 고속류일 때만 다른 arm으로 교체

탐지기 P(≥550) ≥ 0.234인 (시점, h)에서는 mixture arm을, 아니면 이 tweedie15 예측을 씁니다. 즉 “평소 구간의 기본 예측”이 이 arm입니다.

detpool: gpd arm과 가중 혼합

detroute를 base로 두고 gpd arm과 (1−w)·base + w·gpd로 섞습니다. 예시 시점의 창 통계는 base(A) , gpd(B) , 교차(C) → w = 0.25였습니다. A가 base(= 이 실험)의 창 MSE입니다.

자세한 혼합 규칙은 detpool_gpd 페이지 10절에 있습니다.

12 · 재현과 한계

무엇이 남아 있고, 무엇을 주장할 수 없는가

남아 있는 산출물

모델 18개(*.ubj), 손실 로그 18개, 예측 6개, 제출용 forecast.npz/forecast_control.npz, results.json·meta.yaml. 입력 해시는 results.json에 고정돼 있습니다.

주장할 수 없는 것

  • Tweedie 손실이 고속을 더 잘 맞힌다고 말할 수 없습니다. 꼬리 MSE·bias·deviance 모두 나빠졌습니다.
  • “구조도 최적”이라고 말할 수 없습니다. 라운드·깊이·정규화는 point4 레시피 그대로이고, Tweedie에 맞춰 재조정하지 않았습니다.
  • 내부 창 성적으로 방향을 예측할 수 없습니다. 부호가 반대로 나온 사례입니다.

이 실험이 남긴 다음 질문

  1. 꼬리 악화가 계수 축소 때문이라면, p를 낮추거나(예: 1.2) 고속 셀에 별도 가중을 더하면 두 장점을 함께 가질 수 있는가?
  2. 라운드·깊이·정규화를 Tweedie에 맞춰 다시 고르면(예: 더 많은 라운드, 더 작은 η) 꼬리 손실이 줄어드는가?
  3. Tweedie를 단독 제출이 아니라 detroute의 body로 쓸 때의 이득은? 실제로 그렇게 채택됐고, 이 arm은 평소 구간 예측을 담당합니다.

세 질문 모두 이 실행의 산출물만으로는 답할 수 없습니다. 기록된 것은 “손실만 바꿨을 때의 순수 효과”입니다.
