01 / Raw — 원자료에서 시작6 sources · 36,015 h
RAW

모델의 첫 입력은 위성 관측과 모델 실행 파일이다

예측 파일은 이 원자료들의 결과물입니다. 그래서 여기서부터 시작합니다.

이 모델은 예측을 직접 만들지 않습니다. ACE 관측, SUVI 영상, 코로나홀 지도, WSA-Enlil 실행으로 만들어진 두 예측(detroute, gpd)을 읽어 섞습니다. 그래서 문서는 원자료 → 1시간 정렬 → 특징 → 번들 → 예측 2개 → 풀링 순서로 내려갑니다.

SUVI 경도 스트립 — “도달 시각 h에 지구로 흘러오는 태양면은 어느 경도인가”

태양 자전 0.55°/h, 태양–지구 거리 147,858,620.7 km. 속도 v인 유체가 h시간 뒤에 도착한다면 그 유체는 h + age 시간 전에 태양면을 떠난 것이므로 유효 경도는 λ = Ω·(τ_v − (h + age)), τ_v = D/v 입니다. 이 λ를 중심으로 ±5° 띠의 이미지 통계를 가중 평균해 strip_v*를 만듭니다.

// 원자료(이미지 패치) I[lon][lat] · 경도 12칸 × 15° = −90…+90
// 띠 가중치 w_i = |[λ−5, λ+5] ∩ cell_i| / 10
strip_v550_logmed(h) = Σ w_i · log_median_i / Σ w_i
// 커버리지 < 0.5 이면 NaN, age > 6h 면 stale
왜 속도별로 띠가 다른가 — 빠른 유체(750 km/s)는 55시간, 느린 유체(350 km/s)는 117시간 만에 도착합니다. 같은 도달 시각이라도 출발 경도가 다르므로 띠를 5개 속도로 나눠 각각 계산합니다. 느린 유체일수록 더 서쪽(더 이른 시각)에서 출발합니다.

04 / Lineage — 두 예측의 계보4 upstream models
ORIGIN

base와 arm은 이미 만들어진 두 갈래다

풀링은 이 두 줄기를 섞는 일이므로, 줄기의 성격을 먼저 압니다.

base detroute = 몸통↔꼬리 라우팅

몸통 arm tweedie15와 꼬리 arm mixture2comp 사이를 binary:logistic 검출기가 (origin, horizon)마다 확률 p로 고릅니다. 임계값 τ(=)는 채점 전에 비용비로 고정했습니다(놓친 이벤트 ≈4045, 오경보 ≈1233).
몸통 단독 / 꼬리 단독 → 라우팅 . POD , FAR .

arm calib3 gpd = 상한 초과값 대체

같은 level 헤드를 쓰되, p ≥ 0.5인 칸은 550 + exp(로그 초과값)으로 바꿔치기합니다 (peaks-over-threshold). 확률이 0.5를 넘는 순간 값이 계단처럼 바뀌므로 총 , ≥550 — 꼬리는 base보다 낫고 총합은 나쁩니다.

두 모델을 섞는 근거가 여기 있습니다 — 오차가 서로 다른 구간에서 생기고, 꼬리에서 강한 쪽(gpd)을 조금만 섞으면 몸통 손실이 작습니다. 꼬리 arm의 내부는 e2000fs_calib2_mixture2comp 문서에서 이어서 볼 수 있습니다.

07 / Causality — 성숙한 잔차만72h maturity

미래 잔차는 한 칸도 쓰지 않는다

08 / Six numbers — 충분통계cumsum 6개
STATS

창 전체를 6개 숫자로 접는다

MSE(w)는 w에 대한 2차식이므로 계수만 있으면 31점을 전부 즉시 계산할 수 있습니다.
// 잔차 r_b = pred_base − y , r_a = pred_arm − y
// 전체 구간 평균제곱 (창 안 모든 셀)
a0 = mean(r_b²) =   b0 = mean(r_a²) =   x0 = mean(r_b·r_a) =
// 꼬리 구간 (y ≥ 550 셀만, nh = 개)
a1 = mean(r_b² | y≥550) =   b1 = mean(r_a² | y≥550) =   x1 = mean(r_b·r_a | y≥550) =
MSE(w) = (1−w)²·a0 + w²·b0 + 2w(1−w)·x0
tail(w) = (1−w)²·a1 + w²·b1 + 2w(1−w)·x1

왜 이렇게 접히나

(1−w)·r_b + w·r_a 를 제곱하면 r_b², r_a², r_b·r_a 세 항만 남습니다. 평균은 선형이라 창의 누적합 3개씩만 있으면 어떤 w라도 계산됩니다.

누적합 구현

np.cumsum(se_base, axis=0)를 앞에 0행을 붙여 쌓고 c[k] − c[j]로 창 합을 구합니다. 비용은 origin당 O(31).

검산

같은 w에서 직접 계산한 값과 2차식 값의 차이는 — km²/s² 이내(부동소수 오차)입니다. 이 문서 10번 프레임(손풀이)에서 둘 다 표시합니다.
