태양 사진 한 장은 어떻게
72시간 풍속 예측이 되는가

실제 SUVI 이미지 1장에서 출발해 30개 숫자가 되고, 그 숫자가 트리 모델 4개를 거쳐 72개 예측으로 나오는 과정을 한 시점의 실제 계산값으로 따라갑니다. 화면의 모든 숫자는 저장된 파일에서 다시 계산해 모델이 실제로 받은 입력과 대조한 값입니다.

0 · 한눈에

이미지는 신경망에 들어가지 않습니다

이미지 → 숫자는 사람이 정한 고정 산식(학습 없음)이고, 그 뒤는 전부 XGBoost 트리 모델입니다. 각 칸을 누르면 해당 단계로 이동합니다.

읽는 법. 주황 = 이미지에서 나온 숫자, 파랑 = ACE 위성 관측에서 나온 숫자, 보라 = WSA-Enlil 모델 기록에서 나온 숫자. 30개 중 13개가 이미지에서 나옵니다. 모델은 이미지의 픽셀을 직접 보지 않고, 이 13개 숫자만 봅니다.
1 · 원자료 이미지

이미지 1장 = 1280×1280 프레임 → 디스크 774×774 밝기 행렬

GOES-18 위성의 SUVI 망원경이 찍은 극자외선(Fe 195Å) 사진입니다. 밝은 곳은 뜨거운 플라스마, 어두운 곳(코로나홀)은 태양풍이 빠르게 새어 나오는 곳입니다. 예시 시각 T0 보다 1시간 이상 전에 끝난 가장 최근 사진만 쓰므로 이미지는 항상 약 1시간 묵어 있습니다.

위성 자세 때문에 원본 프레임은 약 26° 기울어 있어, 화면에서는 태양 북극이 위로 오도록 돌려 놓았습니다. 격자 위에서 마우스를 움직이면 칸의 값이 나옵니다.

이 이미지가 숫자가 되는 두 갈래

갈래 A 디스크를 경도 12칸×위도 3칸으로 나눠 칸마다 통계 3개(밝기·어두운 비율·유효 비율) → 가운데 위도 줄 12칸만 사용 → 3절에서 5개

갈래 B 중앙값보다 훨씬 어두운 덩어리(코로나홀 후보)를 찾아 면적을 잰다 → 4절에서 7개

그 외 이미지가 얼마나 묵었는지(시간) → 1개

바텀업 ① 픽셀 한 개가 (경도, 위도) 좌표를 얻기까지학습 없음 · 고정 산식

같은 식이 공개 코드 experiments/xgboost_suvi_fusion/features.py의 extract_frame_features()에 그대로 있고, 줄 계산은 model_release/strips.py에 고정돼 있습니다. 모델은 이 좌표를 직접 보지 않고, 아래 5단계를 거쳐 만든 칸별 통계만 봅니다.

복사휘도 복원

SUVI L1b netCDF의 RAD 정수(DN)를 RAD = DN × scale_factor + add_offset으로 실수 복사휘도로 바꿉니다. 이 프레임은 W m⁻² sr⁻¹ 범위이고, 디스크 유효 픽셀의 중앙값 Rref = 입니다. 뒤에 나오는 “어둡다”의 기준이 바로 이 값입니다.

유효 픽셀만 남기기

disk & (DQF == 0) & isfinite(RAD) & (RAD ≥ 0). DQF는 품질 플래그(우주선 타격·결측), disk는 태양 원반 x² + y² ≤ 0.98²입니다. 반지름의 98%까지만 쓰는 이유는 림(가장자리)에서 구면→평면 투영 오차가 커지기 때문입니다.

픽셀 수디스크 π·(0.98·px)² ≈ 개 → DQF·결측 제거 후 개 (유효 %)

기울기 보정 후 반지름 단위로 정규화

FITS 헤더의 CRPIX·CROTA·PC 행렬·RSUN으로 중심을 옮기고 ° 기울기를 풀어, 픽셀 오프셋 (dx, dy)를 태양 반지름 단위 (x, y)로 바꿉니다. 이 프레임의 반지름은 RSUN = px입니다.

x = (PC₁₁·dx + PC₁₂·dy) / RSUN   // 디스크 중심 = (0,0), 림 = |r| = 1
y = (PC₂₁·dx + PC₂₂·dy) / RSUN   // 화면 y는 아래로 증가하므로 부호를 뒤집어 씀

평면 → 구면: 경도·위도

원반 위 (x, y)는 구면의 한 점입니다. z = √(1 − x² − y²)가 “태양 중심을 향한 깊이”이고, B₀는 지구에서 본 태양 자전축 기울기(°)입니다.

z = √(1 − x² − y²)   // x² + y² > 0.98² 이면 원반 밖 → 버림
위도 φ = arcsin( y·cos B₀ + z·sin B₀ )
경도 λpx = atan2( x , z·cos B₀ − y·sin B₀ )   // 서쪽이 +

12 × 3 칸으로 떨어뜨리기

경도는 −90°~+90°를 15°씩 12칸, 위도는 −90°~+90°를 60°씩 3칸으로 나눕니다. 그래서 픽셀 하나는 (i, j) 한 칸에 속하고, 칸 하나의 통계가 그 칸에 속한 수십만 픽셀의 요약이 됩니다.

i = clip( ⌊(λpx + 90°) / 15°⌋ , 0, 11)    j = clip( ⌊(φ + 90°) / 60°⌋ , 0, 2)
36칸 중 12칸만 씁니다. 경도 줄(strip) 피처는 적도대 j = 1(위도 ±30°)만 씁니다. 위 예시의 (6, 2)는 북반구 칸이라 버려지고, (8, 1)·(4, 0) 중에서도 j = 1인 (8, 1)만 살아남습니다. 이 선택은 피처 생성 코드의 lat1 컬럼 필터로 고정돼 있습니다.

이 이미지의 적도 줄 12칸 — 실제 값

밝기 = median(log(1+RAD)) [nats], 어둡 = 칸 픽셀 중 RAD < 0.5·Rref 비율, 유효 = 칸 안 유효 픽셀 비율
2 · 패치 통계: 칸 하나가 숫자 3개가 되는 법

logmed · dark · cover — 세 통계의 정확한 정의

1절에서 픽셀을 12×3칸에 배분했습니다. 이제 칸 하나에 속한 픽셀 수천 개를 숫자 하나로 줄입니다. 쓰는 통계는 딱 세 개이고, 아래 정의가 피처 생성 코드의 전부입니다.

logmed = medianp ∈ 칸 [ log(1 + RADp) ]

평균을 쓰면 3.859 — 밝은 픽셀 1개(P5)에 0.46만큼 끌려갑니다.

실제 칸에는 수천~수만 개 픽셀이 들어가고, 그중 유효 픽셀만 씁니다. flares 같은 국소 발광이 중앙값을 못 흔들게 하려는 선택입니다.

② dark — 어두운 픽셀의 비율

Rref = median( RAD유효 디스크 전체 )
dark = #{ p : RADp < 0.5 · Rref } / #{ p : 유효 }

기준은 그 칸이 아니라 이미지 전체 디스크에서 잡습니다. 칸 기준으로 잡으면 “상대적으로 어두운 칸”이 전부 0.5가 되어 버려 비교가 안 됩니다.

계산 구조 예시 Rref = 100 → 임계값 0.5 × 100 = 50
칸 픽셀 RAD = 10, 20, 40, 70, 90 → 50 미만 3개 → dark = 3 / 5 = 0.60

이 시점 이미지의 실제 Rref는 이라 임계값은 입니다. 어두운 영역 = 코로나홀 후보 = 고속 태양풍의 출발지라는 물리적 가정이 이 통계 하나에 담겨 있습니다.

③ cover — 이 칸을 믿어도 되나

cover = #{ p : 유효 } / #{ p : 칸 전체 }

칸이 원반 가장자리에 걸리거나 결측이 많으면 cover가 떨어집니다. 줄(strip) 단계에서 cover < 0.5면 그 시점 값은 NaN으로 버려집니다.

왜 정확히 이 셋인가. 밝기(logmed)는 “밝은 활성영역/어두운 구멍”의 대비를, dark는 “구멍이 차지하는 비율”을, cover는 “그 판단을 믿을 수 있는지”를 각각 담당합니다. 나머지 통계(10% 분위 등)도 계산되지만 Top30 선택에서 떨어져 모델에 들어가지 않습니다.
3 · 갈래 A: 패치 → 경도 줄 5개

“h시간 뒤에 닿을 바람은 지금 태양의 어느 경도에서 떠났나”

v km/s로 날아오는 바람이 h시간 뒤 지구에 닿으려면 태양에서 τ(v) = 1.4786×10⁸ km ÷ (3600·v) 시간 전에 출발해야 합니다. 태양은 시간당 0.55°씩 자전하므로, 그 출발 지점은 이미지 속에서 λ(h,v) = 0.55° × (τ(v) − (h + 이미지 나이)) 경도(서쪽이 +)에 있습니다. 이 경도 ±5° 폭의 줄이 겹치는 칸 값을 겹친 길이 비율로 가중 평균한 것이 strip 값입니다. 속도 5개 × 72개 시점마다 하나씩 나옵니다.

① 이동 시간 τ — 속도를 “가정”하면 시간이 나온다

τ(v) = 147,858,620.7 km / (3600 · v)
가정한 vτ (h)h = 1일 때 λh = 72일 때 λ

λ가 h가 커질수록 작아지는 이유: 72시간 뒤 도착하는 바람일수록 더 늦게 출발하므로, 지금 이미지에서는 더 동쪽(중앙 쪽)에 있습니다. v가 작을수록 오래 걸려서 더 일찍 출발 → 더 서쪽입니다.

② 왜 속도 5개를 동시에 넣나

바람의 실제 속도를 모르는 채로 줄 위치를 정해야 하므로, 350·450·550·650·750 km/s 다섯 개의 가설을 모두 만들어 모델에 넘깁니다. 모델은 “지금 상황에서 어느 가설이 맞는지”를 5개 값의 조합으로 배웁니다.

750 km/s 가설은 같은 h에서 더 동쪽(중앙 근처), 350 km/s 가설은 더 서쪽(림 근처)을 봅니다. 그래서 5개 줄은 같은 이미지의 서로 다른 경도를 보는 셈이고, 서로 다른 정보를 담습니다.

λ350 − λ750 = 0.55 × (117.35 − 54.76) = 34.4°  // 폭 10° 줄 두 개가 겹치지 않는 거리

③ 이 시점 h에서 남는 5개 숫자 — 계산을 그대로

슬라이더를 움직이면 아래 계산이 함께 바뀝니다. 각 줄의 λ → 겹치는 칸과 겹침 비율 w → 칸 값의 가중합이 그대로 모델 입력입니다.

위 ③의 h를 그대로 그림으로 보여 줍니다.

모델이 실제로 받는 strip 5개 — h에 따라 바뀌는 시계열 (72시간)

15개(속도 5 × 밝기·어두운 비율·유효 비율) 중 모델이 쓰는 건 5개입니다. 특징 30개를 고르는 단계에서 나머지는 탈락했습니다. 이 시점은 5개 줄 모두 72시간 내내 유효(cover ≥ 0.5, NaN 0개)입니다.

값이 비는 두 경로 — 그리고 이 시점은 왜 안 비는가

① 이미지가 늦거나 낡음

슬롯은 관측 종료가 예측 시점보다 1시간 이상 앞선 것(slot ≤ O − 1h)만 씁니다. 공개 지연 때문에 방금 찍은 사진은 쓸 수 없습니다. 그런데 그 슬롯의 관측 종료가 O보다 6시간 넘게 과거면(O − obs_end > 6h) 그 이미지는 stale로 보고 72개 값을 전부 NaN으로 버립니다.

이 시점슬롯 · 관측 종료 · 이미지 나이 h → stale 아님

② 그 줄이 원반을 벗어남

λ가 ±90°를 넘어가면 그 줄은 디스크에 걸치는 칸이 없습니다. 또 가중 평균한 cover가 0.5 미만이면(림에 걸침·결측) 값이 아니라 NaN으로 기록합니다. 그래서 학습 데이터에는 NaN이 남아 있고, 뒤 6절에서 예측 시점 축 전방 채움으로 처리합니다.

4 · 갈래 B: 어두운 덩어리 → 코로나홀 면적 7개

“태양풍이 새는 구멍이 얼마나, 어디에 있나”

① 디스크 중앙값()의 0.35배 또는 0.55배보다 어두운 픽셀을 표시 → ② 3×3 열기·닫기로 잡음 제거 → ③ 보이는 반구의 0.05% 미만인 덩어리 버림 → ④ 구면 보정한 펼친 면적(보이는 반구 대비 비율)을 구역별로 합산. 버튼을 누르면 그 피처가 어느 픽셀의 합인지 분홍색으로 표시됩니다.

후보 전체선택한 피처가 합산하는 픽셀구역 경계

바텀업 ② 검출식 — “어둡다”를 픽셀 단위로 정의하면

① 후보 픽셀과 잡음 제거

후보 = 유효  &  ( RAD < t · Rref ),   t ∈ {0.35, 0.45, 0.55}
후보 → 3×3 열기(opening) → 3×3 닫기(closing) → 8-연결 성분 라벨링

열기로 점 하나짜리 우주선 자국을 지우고, 닫기로 구멍 안쪽의 작은 밝은 반점을 메웁니다. 임계값을 세 개 두는 이유는 “아주 어두운 핵심 구멍(0.35)”과 “느슨하게 잡은 넓은 후보(0.55)”를 모두 피처로 남기기 위해서입니다. (0.45는 계산되지만 Top30에는 0.35·0.55만 들어왔습니다.)

② 면적은 픽셀 수가 아니라 구면 면적

ap = 1 / ( zp · 2π · R☉,px² )   // z = √(1 − x² − y²)
면적(덩어리) = Σp ∈ 덩어리 ap   // 단위: 보이는 반구 = 1
유지 조건: 면적 ≥ 0.0005 (=반구의 0.05%)

원반 가장자리 픽셀은 z가 작아 실제로는 더 넓은 면적을 덮습니다. 이 1/z 가중이 없으면 림 근처 코로나홀이 과소평가됩니다. “면적” 피처는 그래서 픽셀 수 비율이 아니라 보이는 반구 대비 비율입니다.

③ 덩어리 → 구역별 합계 → 모델이 쓰는 7개 (이 시점 실제 값)

적도대 = |위도| ≤ 30°  ·  중앙±15° = |경도| ≤ 15°  ·  중앙±30° = |경도| ≤ 30°  ·  top-k = 면적 순위
피처정의값 (반구 비율)

값은 보이는 반구 = 1 기준 비율입니다. 예: 0.0244는 “보이는 반구 면적의 2.44%가 그 조건의 코로나홀 후보”라는 뜻입니다.

이 절의 한계. 이것은 코로나홀의 물리적 검출이 아니라 “중앙값 대비 어두운 픽셀 덩어리”라는 고정 규칙입니다. 임계값·최소면적·열기/닫기 구조는 사전에 고정됐고 F1/F2로 튜닝하지 않았습니다.

6 · 30개가 한 줄이 되는 법

30개 → 입력 행 237열 (블록 3개)

30개 중 21개는 T0에서 하나의 숫자(상수), 9개는 시간 h마다 하나씩 값이 있는 시계열입니다. 모델은 72시간을 24시간씩 3블록으로 나눠 예측하므로, 블록마다 입력 행을 상수 21 + 9종 × 24시간 = 237열로 만듭니다.

바텀업 ④ 237열이 조립되는 순서design() 한 함수

block = E[:, start : start+24, :][:, :, vary]  // (N,72,20) → (N,24,20) → (N,24,9)
X = hstack([ C[:, const], block.reshape(N, -1) ])  // (N,237)

① 상수 C — 21개, T0의 스칼라

“그 시점에 하나의 값”만 있는 피처입니다. h에 따라 변하지 않으므로 24번 복제하지 않고 한 번만 넣습니다.

② 시계열 E — 9개, h마다 값

원래 E는 20종(27일 회귀 4 + strip 15[속도 5 × 통계 3] + enlil_dt_target 1)입니다. 그중 Top30에 든 9종만 씁니다.

20 × 72 = 1,440개 후보 중 9 × 24 = 216개가 블록 하나의 입력이 됩니다. 이 9개(와 상수 21개)는 미리 고정된 목록이고, 예측 시점마다 다시 고르지 않습니다. 목록은 과거 공식 구간 성적을 참고해 정해진 이력이 있습니다.

③ 24시간만 자른다

한 예측 시점의 E는 72행이지만, 블록 b는 자기 구간만 봅니다. 세 모델은 같은 C를 공유하고 E만 다릅니다.

Block 0 → E[:, 0:24, :]  ·  Block 1 → E[:, 24:48, :]  ·  Block 2 → E[:, 48:72, :]
f0, f1, f2 : ℝ²³⁷ → ℝ²⁴  // 각 24개 출력, 이어 붙이면 72

④ 펼치는 순서는 “시간 우선”

reshape(N, -1)은 (24, 9)를 행 우선으로 펼칩니다. 즉 h=1의 9개, h=2의 9개, … h=24의 9개 순서입니다. 그래서 22~30열이 h=1, 31~39열이 h=2 … 가 됩니다.

X[1..21] = C  ·  X[22..30] = E(h=1)  ·  X[31..39] = E(h=2)  ·  …  ·  X[229..237] = E(h=24)

⑤ 결측은 “예측 시점 축”으로 전방 채움

7 · 모델 구조

트리 모델 4개 → 두 갈래 예측 → 비율 w로 섞기

같은 237열 입력을 기준 모델 detroute(body·tail·탐지기의 조합)와 gpd arm이 각각 받아 72개 예측을 만들고, 마지막에 두 예측을 (1−w)·detroute + w·gpd로 섞습니다.

입력 237열 × 블록 3개 (h1–24 · h25–48 · h49–72) ← 6절

① 기준 모델 detroute (“고속류가 올 것 같으면 tail, 아니면 body”)

body — 평소 풍속

XGBoost 블록 3개. 트리 1개가 24시간을 한 번에 출력(벡터 리프), 깊이 3 · 900 라운드, Tweedie(p=1.5) 손실.

출력: 72개 속도

tail — 고속류 전용

level · P(y≥550) · gap 3개 머리 × 3블록. level + P·(gap − level)로 합성, 고속 쪽으로 기움.

출력: 72개 속도

탐지기 — 고속류 확률

이진 로지스틱 XGBoost, 깊이 4 · 400 라운드. 입력 237열 + 시간 인덱스 h.

출력: P(≥550) 72개
각 시간마다 P ≥ 0.234 이면 tail, 아니면 body → detroute 72개 (0.234 = 오경보 비용 1233 ÷ (1233+놓침 비용 4045), 사전 고정)

② gpd arm (“고속류 구간은 꼬리 분포로 교체”)

level

고속 샘플에 4배 가중을 준 MSE 트리 (900 라운드). 평소 속도.

P

y≥550 확률 (400 라운드).

excess

log(y − 550) 회귀 (400 라운드).

P ≥ 0.5 이면 550 + exp(excess), 아니면 level → gpd 72개
최종 = (1 − w)·detroute + w·gpd   (w는 0~0.75를 0.025 간격 31점에서 최근 성숙 잔차로 고름, 10절)

F1 평가용 모델은 정답이 2026-02-26 이전인 데이터로만 학습합니다(원점+144h 마스크). 예시 시점은 F1 구간 안입니다. gpd arm의 세 머리는 보관되지 않아 최종 gpd 곡선만 보입니다.

바텀업 ⑤ 세 모델은 각각 무엇을 최소화하는가

같은 237열 입력, 같은 트리 구조(깊이 3 · 900 라운드), 다른 손실함수. XGBoost는 손실의 그래디언트 g와 헤시안 h만 보고 트리를 자라게 합니다.

body — point4 가중 제곱오차

L = ½ · w · (μ − y)²,   w = 4 (y ≥ 550) 또는 1
g = w(μ − y),   h = w   // w는 horizon별 평균이 1이 되게 정규화
리프 값 = −G/(H + λ),   λ = 5,   반영량 = 0.03 × 리프 값
계산 예시 μ = 500, y = 650, w = 4 → g = 4(500−650) = −600, h = 4
그 잎의 합이 G = −600, H = 4이면 리프 값 = 600/(4+5) = 66.7
학습률 0.03 → 이번 라운드에서 예측이 +2.0 올라감 (500 → 502.0)

w가 정답 기준이라는 점이 중요합니다. “실제로 고속이었던 샘플”의 오차를 4배로 세므로, 고속 구간을 놓치면 벌점이 커집니다. 대신 손실의 최소점이 조건부 평균에서 살짝 비뚤어집니다.

tail — level + P·(gap − level)

L̂ = level 트리  // point4 손실
P̂ = clip( 확률트리 , 0, 1)  // 정답 1[y ≥ 550], MSE로 학습
Ĝ = gap 트리 + meanevent(y)  // 잔차로 학습하고 평균을 되더함
tail = L̂ + P̂ · (Ĝ − L̂)
계산 예시level 470, P 0.6, gap 650 → 470 + 0.6×(650−470) = 578
gap 학습event = (y ≥ 550).any(h축) 행만 사용 → resid = y − meanevent(y) → 학습 후 평균 재가산

P̂는 tail 내부의 확률 머리이고, 아래 탐지기의 P와는 다른 모델입니다. 둘 다 기준은 550이지만 학습 대상이 다릅니다(머리는 horizon 단위, gap은 블록 단위).

탐지기 — “이 (시점, h)는 고속인가”를 따로 학습

입력 = [ 237열 블록 피처 , h ]  // 238열, h마다 한 행
3개 분류기(블록별), binary:logistic · 깊이 4 · 400 라운드
P̂det ≥ 0.234 → tail,   아니면 → body

임계값은 성능으로 고른 값이 아니라 비용비에서 나옵니다. 고속을 놓칠 때의 손실 ≈ 4,045, 오경보의 손실 ≈ 1,233이라 베이즈 임계값은 1233/(1233+4045) = 0.2336 → 0.234로 고정했습니다.

이 시점 h = 의 실제 계산 시작값(base margin) =

라우팅은 h마다 독립이라, 한 시점의 72시간 예보 안에서 어떤 시간은 body, 어떤 시간은 tail이 됩니다. 그래서 detroute 곡선은 두 모델을 이어 붙인 모양이 됩니다(아래 그림).

왜 이 구조를 쓰나. 두 arm을 “정답을 미리 안다”고 가정하고 섞으면 총 MSE 2,679.8 · 고속 5,380.6까지 내려갑니다(오라클 진단). 즉 정보는 두 arm 안에 이미 있고, 부족한 것은 “어느 (시점, h)가 고속인가”를 맞히는 일입니다. 탐지기는 그 선택만 담당합니다.

8 · gpd arm: 꼬리만 따로 맞히는 모델

“550을 넘는다면, 얼마나 넘는가”를 따로 학습

detroute는 고속 여부에 따라 두 arm을 통째로 골라 쓰는 방식입니다. gpd arm은 반대로 같은 모델 안에서 고속일 때만 예측을 교체합니다. 세 머리를 각각 학습하고, 확률이 0.5를 넘는 (시점, h)에서만 level 예측을 꼬리 예측으로 바꿉니다.

level — 평소 속도

L̂ = point4 트리(x)
// y≥550에 4배 가중, 900 라운드

P — 550을 넘을 확률

P̂ = clip(트리(x), 0, 1)
// 정답 1[y≥550], MSE, 400 라운드

excess — 초과량

Z = log( max(y − 550, 1) )
Ẑ = clip(트리(x), 0, log 2450)
// 초과가 있는 블록 행만 학습

조립식

route = ( P̂ ≥ 0.5 )
ŷgpd = U + exp(Ẑ)   if route   // U = 550
ŷgpd = L̂   otherwise
마지막에 clip(ŷgpd, 1, 3000)
계산 예시 L = 480, P = 0.70, Z = log(100) → route = 참
ŷ = 550 + exp(log 100) = 650
같은 시점에서 P = 0.40이었다면 ŷ = L = 480 (level 그대로)

이름은 gpd지만 일반화 파레토 분포를 적합하지는 않습니다. 실제 구현은 “550 초과 발생(P)”과 “초과량의 로그(Z)”를 XGBoost로 회귀하는 peaks-over-threshold 근사입니다. Z를 로그로 둔 덕분에 꼬리 오차가 절대량이 아니라 비율로 벌점화됩니다.

0.5라는 문턱은 확률을 매끄럽게 섞는 대신 “넘는다/안 넘는다”를 딱 잘라 씁니다. 그래서 gpd 곡선은 level 곡선과 꼬리 곡선 사이를 계단처럼 오갑니다.

arm은 파일 하나입니다. 학습이 끝나면 72시간 예측 전체를 runs/gpd_v1/forecast.npz에 저장하고, detpool(pool_lane)은 그 배열을 다시 학습하지 않고 그대로 읽어 씁니다. 같은 자리에 넣을 수 있는 다른 arm도 있습니다 — era(월별 오차로 반복 재가중), mixture(level+확률+gap), spectral(FFT 기반 오차 벌점). 10절의 w는 “이 arm을 얼마나 믿을지”를 고르는 값입니다.
9 · 트리 한 번 계산해 보기

탐지기가 시간 뒤 확률을 계산하는 과정

XGBoost 모델은 수백 그루의 작은 결정 트리입니다. 각 트리는 “이 값이 기준보다 작은가?”를 4번 묻고 도착한 잎(leaf)의 숫자를 내놓으며, 모든 잎 값을 더한 뒤 확률로 바꿉니다. 아래는 이 시점의 실제 모델 파일에서 꺼낸 첫 세 그루입니다. 주황색 이름 = 이미지에서 나온 피처.

벡터 리프. body·tail은 multi_strategy='multi_output_tree'(num_target=24)입니다. 즉 리프 하나가 숫자 하나가 아니라 24차원 벡터를 들고 있습니다. 그래서 “트리 1그루 = h1~h24를 동시에 보정”이 되고, 900 라운드 뒤 24개 출력이 함께 완성됩니다. 탐지기는 이진 분류기라 리프가 스칼라입니다(아래 그림).

같은 입력, 다른 손실 — Tweedie가 바꾼 것

body(tweedie15)는 point4의 4배 가중 제곱오차 대신 Tweedie deviance를 씁니다. 분산이 평균의 p제곱에 비례한다고 보는 손실(Var = φ·μ^p, p = 1.5)이고, 코드의 그래디언트·헤시안은 다음과 같습니다.

g = Sp( μ1−p − y·μ−p ) = (S/μ)p (μ − y)
h = Sp( (1−p)·μ−p + p·y·μ−p−1 ) = (S/μ)p( (1−p) + p·y/μ )
S = 500, p = 1.5,   h ← max(h, 10⁻⁶·Sp)  // 헤시안이 0 이하로 갈 수 있어 하한
예측 μ(500/μ)1.5오차 μ−y = −150|g|
3002.152−150322.8
4001.398−150209.6
5001.000−150150.0
6000.761−150114.1
7000.604−15090.6

같은 150 km/s 과소예측이라도 낮은 예측값에서 더 세게 밀어 올립니다. 즉 Tweedie 손실은 “상대오차”를 벌점화하고, point4처럼 550에서 가중치가 계단으로 뛰지 않습니다. “고속을 더 강하게 학습한다”와는 다른 이야기입니다(표에서 μ가 클수록 |g|가 작아집니다). Sp를 곱하는 이유는 그래디언트를 O(1)로 유지해 reg_lambda=5가 원래 의미를 갖게 하려는 것입니다.

잎 값을 400그루 누적하면

질문(분할)이 어떤 입력에서 나왔나

모델 파일의 모든 트리에서 분할 횟수를 센 비율(3개 블록 평균, F1 학습본).

분할 횟수는 영향력의 근사일 뿐입니다. 이미지 피처는 30개 중 13개(43%)인데 분할의 약 절반을 차지합니다. 쓸모는 있지만 압도적이라는 뜻은 아닙니다.

10 · 마지막 섞기와 결과

w는 최근 한 달 성적으로 고릅니다

예시 시점 직전까지 72시간치 정답이 모두 나온(그 시점 + 72시간 ≤ T0) 최근 개 시점의 잔차만 모아, 31개 후보 w마다 “전체 MSE”를 계산합니다. 단, 같은 구간의 고속(≥550) MSE가 detroute보다 나빠지는 w는 후보에서 뺍니다. 가장 낮은 전체 MSE의 w가 이 시점의 w입니다. 재학습은 없습니다.

바텀업 ⑥ 잔차 세 개로 2차식을 만들고, 최소점을 격자에 스냅pool_lane.choose_weights

① 잔차 세 종류만 저장한다

se_base = (base − y)²  ·  se_arm = (arm − y)²  ·  cross = (base − y)(arm − y)

혼합 예측의 오차는 (1−w)(base−y) + w(arm−y)이므로, 제곱해서 평균하면 아래 세 평균만 있으면 됩니다. 72개 horizon을 모두 같은 w로 섞기 때문에 horizon별로 쪼개지 않고 전부 더해 씁니다.

② 창(window)을 자른다 — 성숙한 과거만

matured(k) = #{ k′ : origink′ + 72h ≤ origink }  // searchsorted
사용 구간 = [ matured(k) − 2160 , matured(k) )  // 최근 2,160개 시점

아직 72시간이 지나지 않은 시점의 정답은 미래 정보이므로 후보에서 제외합니다. 이 한 줄이 정보 누수를 막는 장치입니다.

③ 평균 세 개 → MSE(w)는 w의 2차식

A = mean(se_base),   B = mean(se_arm),   C = mean(cross)  // 창 전체
MSE(w) = (1−w)²·A + w²·B + 2w(1−w)·C
w* = (A − C) / (A + B − 2C)

A는 detroute의 창 MSE(= w=0), B는 arm의 창 MSE(= w=1), C는 두 오차가 같은 방향으로 틀린 정도입니다. C가 작을수록 두 모델이 서로 다른 쪽으로 틀렸다는 뜻이라 섞을 이득이 커집니다.

④ 고속 구간 보호 제약

tail(w) = (1−w)²·A₁ + w²·B₁ + 2w(1−w)·C₁   // 정답 ≥ 550인 셀만
허용 조건: tail(w) ≤ tail(0) = A₁

전체 MSE만 보고 w를 고르면 고속 구간이 나빠질 수 있습니다. 그래서 “고속 MSE가 detroute보다 나빠지지 않는 w”만 남기고 그 안에서 전체 MSE 최소를 고릅니다. 이 제약 때문에 w가 0에 붙는 시점도 생깁니다(전체 w의 %).

⑤ 격자에 스냅 + 안전장치

w ∈ {0, 0.025, 0.050, …, 0.750}  // 31점, 사전 고정
w ← argminw, 허용 MSE(w)

연속 최적점 w*를 그대로 쓰지 않고 미리 정한 격자에서 고릅니다(과최적화 방지·재현성). 그리고 창이 너무 짧으면 학습을 포기합니다: 성숙 시점 < 48개 또는 고속 셀 < 50개면 w = 0(detroute 그대로).

이 설계가 하는 말. “어느 모델이 나은가”를 미래가 아니라 과거 잔차로 판단하고, 판단에 쓰는 통계는 세 개의 평균뿐이며, 그 위에 고속 성능 하한과 표본 최소 조건을 얹었습니다. 학습되는 파라미터는 하나도 없습니다 — 매 시점 w만 다시 계산합니다(시점당 약 μs).

후보 w별 최근 구간 전체 MSE

이 시점 한 개의 결과 (72개 평균 MSE)

전체 4,970개 시점 평균

이 시점은 설명을 위해 탐지기가 실제로 발동한 사례를 골랐습니다. 전체로 보면 개선폭은 작습니다(총 MSE −4.3, 고속 −378). 시점의 약 48%에서 좋아지고 약 48%에서 나빠집니다.

숫자를 읽을 때의 세 가지 주의. ① 10절의 w는 과거 잔차로만 정해집니다. 미래에 새로 발생하는 고속류를 보장하지 않습니다. ② 고속 구간 제약은 “과거에 550 이상이었던 셀”의 성능을 지키는 장치입니다. ③ 이 페이지의 Top30 목록은 과거 공식 결과를 참고해 고른 이력이 있어, 독립적인 신규 구간 성능으로 읽을 때는 그 점을 감안해야 합니다.
